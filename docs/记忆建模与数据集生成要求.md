# 记忆建模与数据集生成要求

> 说明：需要删除或替换的原内容使用删除线标记，修改后的内容紧接在删除线后面。

## 记忆的核心作用

> 识别用户自定义表达；补全省略参数；识别应用和业务；处理时间表达；复用历史澄清结果；判断何时必须向用户追问。

记忆不是检索到就直接使用，而是需要结合当前输入、用户事实记忆和环境事实记忆进行判断：证据充分时补全，证据不足或存在冲突时向用户追问。

## 用户事实记忆

### 核心问题

关于某个特定用户，经过明确确认或有足够历史证据，可以在适用条件和有效时间内继续使用的声明性知识。

- 用户明确声明的事实、表达映射或偏好，可以通过单次明确表达建立。
- 根据历史行为归纳的偏好，需要多次相互独立且一致的历史证据支撑。
- 一次历史行为只表示某个事件曾经发生，不能直接视为用户的长期偏好。
- 需要区分"仅对本次任务的确认"和"可以在未来复用的长期记忆确认"。

### 主要存储对象

用户属性、个性化表达、默认值、偏好、纠错。

生成数据时，需要区分以下信息：

- 用户稳定事实：套餐、权益、用户明确设置的默认值等；
- 个性化表达映射：用户表达与标准应用、业务、时间或参数之间的映射；
- 行为偏好：根据多次历史行为归纳得到的、具有条件性和概率性的偏好；
- 历史事件：某次任务中发生过的行为，本身不等于长期偏好。

### 静态用户事实

关系型数据库，仅当取值发生变化时更新。

- 用户ID；
- 套餐信息：已订购的业务权益、保障的业务和应用范围等。

静态用户事实需要具备当前状态或生效时间，避免使用已经变更的套餐和业务权益。

### 动态用户事实

~~保障单据/日志、意图交互历史记录。~~

保障单据、日志和意图交互历史记录是形成动态用户事实的证据来源。经过确认、归纳或纠正后，可以形成可复用的个性化表达、默认值和条件偏好。

#### 内容

##### 用户个性化表达

> * 时间：马上，稍后这类词
> * 参数：清晰一点，时延不要太高 分辨率不要太低：>=720p; 有档位的概念

- 应用别名；
- 业务别名；
- 时间表达习惯：开始时间、结束时间、持续时间；
- 参数表达映射：模糊表达到具体参数的映射关系，如分辨率、时延。

需要区分个性化表达的证据来源：

- 用户明确声明，例如"以后我说老业务，就是指抖音直播"；
- 用户在澄清过程中明确确认表达的含义；
- 用户纠正Agent后得到最终含义；
- 多次历史会话形成稳定、一致的表达映射；
- Agent根据任务结果推测，但用户尚未确认。

用户确认本次任务参数，不一定等于确认长期表达映射。例如，用户同意本次将"高清"处理为1080P，不代表以后"高清"始终等于1080P。

同一个表达对应多个目标取值时，需要结合当前条件消歧；条件不足时必须追问。

##### 应用—业务选择偏好

> 开直播：可能是抖音或者快手，不一定要说出来。

用户表达不完整时，在某类业务下通常选择哪个应用或具体业务。

- 业务到应用的选择偏好；
- 应用到业务的选择偏好；
- 应用—业务组合偏好；
- 候选排序；
- 排斥组合。

需要区分：

- 用户明确指定的默认选择；
- 根据多次历史行为归纳的常用选择；
- 仅在特定场景下成立的条件偏好；
- 仅在某次任务中出现的历史选择。

一次应用—业务选择不能直接生成长期偏好。多个候选的证据接近时，应向用户追问，不能直接选择最高频候选。用户当前明确提供的应用或业务优先于历史偏好。

##### 时间模式偏好

需要结合历史记录判断。

- 常用开始时间、结束时间、持续时间；
- 日内规律；
- 星期规律；
- 工作日、周末规律；
- 节假日、热点事件规律，只在某个时间段内成立；
- 周期规律：每日、每周、每月、每季度、每年。

时间模式偏好需要包含适用条件和有效时间。节假日、赛事和热点事件形成的规律属于临时偏好，事件结束后不能继续作为默认值使用。

当前时间表达与历史时间偏好冲突时，以当前明确表达为准。历史中存在多个常用时间且无法唯一确定时，应向用户追问。

##### 体验参数偏好

针对特定业务或者应用。

- 首选值；
- 备选值；
- 排斥值；
- 范围偏好；
- 优先级偏好；
- 多参数组合偏好。

体验参数偏好必须明确其适用对象，包括特定应用、特定业务或特定应用—业务组合。

多参数组合偏好应作为整体使用，不能将其中的单个参数任意拆分后应用于其他场景。用户体验参数偏好不能突破当前套餐权益、应用能力和业务规则规定的合法范围。

## 数据集生成要求

数据集不能只生成"利用记忆成功补全"的正样本，还需要生成"不能直接使用记忆、必须追问"的负样本。

### 个性化表达理解

- 应用别名；
- 业务别名；
- 时间表达；
- 参数模糊表达；
- 一对一和一对多表达映射；
- 表达映射纠正；
- 表达映射随时间更新；
- 未经确认的候选表达；
- 条件不足、必须追问的表达。

### 参数缺失补全

- 业务补全应用；
- 应用补全业务；
- 应用—业务联合补全；
- 时间参数补全；
- 体验参数补全；
- 多参数组合补全；
- 根据排斥组合排除候选；
- 多个候选接近时不补全并追问。

### 条件偏好推断

- 单条件偏好；
- 多条件联合偏好；
- 全局偏好；
- 场景偏好；
- 周期偏好；
- 临时偏好；
- 用户显式偏好；
- 历史行为归纳偏好；
- 条件完全匹配；
- 条件部分匹配但证据不足；
- 条件不匹配；
- 多个偏好发生冲突。

### 记忆更新与冲突处理

- 记忆巩固；
- 用户纠正；
- 新偏好覆盖旧偏好；
- 用户撤销偏好；
- 全局偏好细化为条件偏好；
- 偏好随时间变化；
- 临时规律到期；
- 显式偏好与行为偏好冲突；
- 用户事实与环境事实冲突；
- 当前明确输入与历史记忆冲突。

### 追问决策

- 无相关记忆；
- 只有一次历史行为；
- 记忆证据不足；
- 多个候选接近；
- 当前条件与记忆条件不匹配；
- 记忆已经失效；
- 当前输入与历史记忆冲突；
- 记忆推断结果违反业务规则；
- 记忆推断结果超出用户套餐权益；
- 关键参数必须由用户明确确认。

### 基本判断原则

- 当前用户明确表达优先于历史记忆；
- 用户显式声明优先于历史行为归纳；
- 环境事实决定推断结果当前是否真实、合法和可执行；
- 历史事件不能自动转化为长期偏好；
- 任务确认不能自动转化为长期记忆确认；
- 只有在条件匹配、记忆有效、证据充分且不存在明显冲突时，才能使用记忆补全参数；
- 不能唯一确定目标值时，正确结果应是追问，而不是强行选择最高频候选。

### 记忆建模与四层 GT 对应关系

| data_design 类别       | 对应 Ground Truth 层                              | 对应代码字段                                                 | MT 选择路径                                                  | 说明                                                         |
| ---------------------- | ------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **用户个性化表达**     | `personalization_gt.expression_mappings`          | `expression_type: app_alias / service_alias / quality_expression / speed_expression / time_expression` | → `app_alias_mapping` / `service_alias_mapping` / `quality_grade_mapping` / `speed_expression_mapping` / `time_expression_mapping` | 用户表达与标准应用、业务、时间或参数之间的映射关系           |
| **应用—业务选择偏好**  | `personalization_gt.app_business_preferences`     | `direction: business_to_app / app_to_service`                | → `service_to_app` / `app_to_service` / `app_service_combo`  | 用户表达不完整时在某类业务下通常选择哪个应用或具体业务       |
| **时间模式偏好**       | `conditional_gt`                                  | `fact_type: conditional_time_preference`                     | → `daily_time_preference` / `weekly_preference` / `weekday_weekend_preference` / `temporary_preference` / `periodic_preference` | 结合历史记录判断的日内/星期/工作日周末/节假日周期规律        |
| **体验参数偏好**       | `personalization_gt.experience_param_preferences` | `preferred_bundle / fallback_bundle / rejected_values`       | → `preferred_value` / `fallback_value` / `rejected_value` / `multi_param_bundle` / `scope_restriction` | 针对特定应用或业务的首选值、备选值、排斥值、多参数组合       |
| **记忆更新与冲突处理** | `changeable_gt`                                   | `fact_type: role_change / event_driven_change`               | → `memory_correction` / `preference_change`                  | 纠正、新偏好覆盖旧偏好、临时规律到期、显式偏好与行为偏好冲突 |

### static_gt 的作用

`static_gt` 不直接参与 Memory Targets 选择，其字段通过以下路径被引用：

| 字段                          | 使用路径                            | 说明                                    |
| ----------------------------- | ----------------------------------- | --------------------------------------- |
| `static_gt.identity`          | `session_generator.py` → LLM prompt | 用户画像描述，作为对话生成的上下文      |
| `static_gt.allowed_scenarios` | `timeline_planner.py` → 场景选择池  | APP × 业务 × 支持分辨率的合法场景列表   |
| `static_gt.frequent_apps`     | 多处以场景白名单形式间接使用        | 常用 APP 标准名列表，用于校验和场景推导 |
