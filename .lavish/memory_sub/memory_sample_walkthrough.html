2 检索与槽位提取四步流水线对账

执行步骤 输入与匹配动作 产出的结构化槽位状态
Step 1：否定子句分离 从用户话语“明早8点又要去崇礼钻山洞那段直播，别按上次卡顿那回”中拆出正向查询与负向过滤条件 status != sla_degraded 正向查询词：去崇礼钻山洞那段直播
排除条件：exclude_status = sla_degraded
Step 2：向量检索与同行槽位提取 用 text-embedding-v4 检索命中 EXP_MAP_07（余弦相似度 0.89），直接读取同行结构化列 提取同行列：venue = 京礼高速隧道群，primary_app = 车载高清直播
Step 3：历史单据筛选与废单过滤 按 venue = 京礼高速隧道群 查单据表，并对命中负向特征的 TK_21 (sla_degraded) 做权重衰减过滤，锁定 TK_25 提取同行列：priority = P1，base_duration = 90min
Step 4：二阶段关联表补全 顺着 primary_app = 车载高清直播 查 service_to_app，顺着 venue = 京礼高速隧道群 查经验表 补全：aux_app = 行车遥测日志后台上传 (P3)，preheat = 15min (start_time = 07:45, duration = 105min)

3 核心工程收益小结

  • 语义泛化靠向量，槽位准确靠同行结构化列：向量只负责把口语“钻山洞”定位到 EXP_MAP_07 这一行，后续拿到的 京礼高速隧道群、P1、90min 全是从同行结构化字段里直接读出来的，避免参数生成错误。
  • 二阶段关联补全不怕用户少说话：用户嘴上只提了直播，系统通过 service_to_app 和场馆经验表自动把后台遥测上传和提前 15 分钟预热全部配齐。
