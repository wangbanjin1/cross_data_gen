Agent 评测角度与指标思路

评测带记忆的多轮 Agent，如果只看最终输出的工单或回复对不对，很难分清模型是“真查到了历史依据”还是“碰巧答对了常见默认值”，也看不出问题到底出在检索、快慢路径判断还是参数计算上。整体可以从“记忆检索与依据核对”、“快慢路径与参数计算”、“边界克制与运行稳定性”三个角度切入（查看示例 →）：

① 记忆检索与依据核对（看查没查全、结果是不是真靠查出来的记录算的） —— 参考 GroundEval、LongMemEval、LoCoMo-Plus、RHELM
  • 多源联合召回率（Joint Recall@K）：一条请求往往同时用到历史单据、周期习惯和场馆经验；按任务实际依赖的记录集合统计完整召回比例，看跨源信息找没找全。
  • 有依据准确率（Grounded Accuracy）：先看检索有没有命中目标记录，再看生成的参数对不对；如果检索阶段没捞到对应依据，即使输出值与默认档位一致，也直接记 0 分。
  • 新状态覆盖率（Update Override Rate）：用户偏好发生过变更、言行不一致或事后有实测回执更新时，统计采纳最新有效记录、排除过期旧单和退订废单的比例。
  • 相似记录区分率（Contrastive Discrimination）：同一地点有多张相似单据且带正向或排除指代时，同时看目标记录召回率与负样本误召回率。
② 快慢路径判断与参数规则校验（看该快则快、该问则问、加减算准） —— 参考 ClarifyMT-Bench、Clarification Is Not Correction、RuVerBench、Agent-as-a-Judge
  • 快慢路径准确率（Route F1 / 过度反问率 & 盲目执行率）：分开统计两类问题——信息已经够用却还在追问的过度澄清率，以及缺参数或时间段重叠却未经确认直接执行的盲目执行率。
  • 澄清命中率与收敛轮次（Clarification Precision & Turns）：看慢路径反问能不能一次性问到缺失或冲突点上，以及平均几轮对话能把工单敲定。
  • 跨轮次槽位保持率（Slot Retention Rate）：用户在第 2~3 轮补充说明或只改某一个参数后，看第 1 轮已经确认好的其他槽位有没有被顺手改乱或弄丢。
  • 规则脚本校验通过率（Rule-Verified Pass Rate）：不用大模型主观打分，直接用脚本核对“历史基准时长 + 对话增减 + 场馆提前预热”的时间加减、多规则优先级和主辅双业务字段。
③ 边界克制、抗幻觉与运行稳定性（看按需调用记忆、缺少依据时如实拒答、多次跑都稳） —— 参考 PersonaMem-v3、TWIST、τ-bench / τ2-bench
  • 无关问题误触发率（Over-Personalization FPR）：遇到普通通信常识问答或日常闲聊时，统计强行往回复里塞个人历史单据的误触发比例（越低越好）。
  • 未知场馆拒答率与幻觉率（Abstention & Hallucination Rate）：问到从未出现过的陌生场馆或域外话题时，看模型是如实说明无记录并反问，还是套用其他场馆的参数。
  • 多次运行一致性（passk）与耗时开销：同一条任务连续独立跑 k 次（如 k=3, 5）全部通过的比例（passk），同时统计快/慢路径的 P95 时延与 Token 消耗。

评测角度 核心指标与计算口径 参考论文
1. 记忆召回与依据核对 ① 多源联合召回率（Joint Recall@K）与全命中率（All-Hit Rate）
统计单条任务依赖的全部记忆项（历史单据、关联辅业务、场馆经验、口语映射）在检索 Top-K 中的召回比例（已召回项数 / 应召回总数），以及全部找齐的完整命中比例 		• PersonaMem-v3：评测跨非对话日志与历史对话的多源信息联合召回率。
• LoCoMo-Plus：评测查询词与历史记录字面不重合时的语义召回表现。
② 有依据准确率（Grounded Slot Accuracy）与反事实敏感度
仅当对应单据或经验在检索阶段被成功召回、且最终输出槽位等于标准值时才记 1 分（未召回依据直接记 0 分）；同时修改召回记录中的数值，看输出槽位是否跟着同步变化 		• GroundEval：通过依据对齐与反事实参数替换，区分“基于召回记录得出结果”与“未命中记录但与默认值巧合一致”的情况。
2. 时效覆盖与抗噪区分 ① 状态更新覆盖率（Update Override Rate）与旧值残留率（Stale Leak Rate）
在偏好升级、言行不一或事后回执修正的场景下，统计采用最新有效状态的比率，以及误输出过期参数或退订废单（aborted）的残留率 		• LongMemEval：通过多时间戳状态更新题，评测新状态覆盖旧状态的准确率。
• RHELM：评测事后客观执行日志更新对话预期后的最新状态追踪率。
② 相似记录正负区分度（Positive Hit & Negative Rejection Rate）
同地点多张相似单据下，统计“命中目标单据且排除负向指代单据（如卡顿单）”的比例，以及把 1~2 次偶发单据误当成长期习惯的误报率 		• RHELM：评测相似事件按特征筛选与排除法指代的准确率。
• PersonaMem-v3：评测区分单次偶发记录与多次重复长期习惯的准确率。
3. 快慢路径与多轮澄清 ① 路由 F1、过度澄清率（Over-Clarification）与盲目执行率（Premature Action）
在信息齐全样本上统计不反问直接闭环的比率；在缺槽位、时间冲突或多单歧义样本上统计主动停下并反问的比率 		• ClarifyMT-Bench：在明确指令与欠指定/冲突指令混合集上，联合评测直接执行与主动提问的边界。
• τ-bench / τ2-bench：考核工具调用前是否按规定先向用户确认缺失或冲突参数。
② 澄清问题命中率（Question Targeting）与已确认槽位保持率（Slot Retention）
检查反问是否问准全部缺失或冲突字段（不漏问、不偏离重点追问）；在用户第 2 轮回复澄清后，核对第 1 轮已确认槽位未被篡改的比率 		• Clarification Is Not Correction：评测多轮澄清与局部修改过程中，已确认历史槽位的保持率。
4. 参数计算与多规则合成 ① 槽位精确匹配率（Exact Slot Match）与整单通过率（Ticket EM）
逐字段核对生成工单的 venue / start_time / end_time / duration / priority / primary_app / aux_app：错任意一个字段即判整单未通过（Ticket EM = 0） 		• RuVerBench：通过确定性规则脚本逐字段校验工具参数与复合数值约束。
• τ-bench / τ2-bench：以最终落库状态与标准目标状态的完全相等作为核心判据。
② 时间加减与规则优先级合规率（Arithmetic & Priority Compliance）
用规则脚本校验时间加减（基准时长 + 对话增减 + 场馆提前预热）、时间窗重叠顺延/合并，以及多规则冲突时是否按四级优先级顺序取值 		• RHELM：评测多规则冲突裁决与时间区间冲突重排的准确率。
• RuVerBench：使用代码断言替代大模型主观打分，消除时间加减评测误差。
5. 个性化克制与安全边界 ① 干扰会话克制率（Restraint Rate）与过度个性化误触发率（FPR）
在穿插的通用知识问答或日常闲聊上，检测回复中是否混入个人历史单据或业务档位，统计不强行带入无关记忆的克制比例 		• PersonaMem-v3：设置通用问答对照题，评测模型克制不滥用个人记忆的能力。
• TWIST：构造高表面相似度负样本，测试主动记忆助手的误触发率。
② 未知前提拒答率（Abstention Rate）与参数幻觉率（Hallucination Rate）
针对历史无记录的陌生场馆或域外话题，统计如实告知无记录并引导补充的比例，以及凭空编造档位/时长的幻觉比例 		• LongMemEval / GroundEval：加入缺失事实前提的不可回答问题，评测如实拒答率与抗幻觉能力。
6. 运行稳定性与错因定界 ① 多次运行一致性（passk）、分阶段错因占比与耗时开销
计算同一任务连续独立执行 k 次全部通过的比率（pass3）；并对失败样本自动统计各环节占比（检索漏召回 % / 路由错 % / 时间计算错 %）及 P95 时延 		• τ-bench / τ2-bench：提出 passk 指标衡量多次独立运行的稳定性。
• Agent-as-a-Judge：对执行轨迹做分步核查，自动定位失败发生在哪一环节。
